# 15 秒 PV 撮影計画書

Optical Illusion Museum の見どころを 15 秒の動画で伝えるための計画。撮影はアプリを実機の Chrome で動かして画面収録する。カット割り・カメラ・演出の時間・テロップ・収録手順・編集指示をまとめる。

- 絵コンテの画像: `Docs/screenshots/storyboard/`(git 管理外。[再生成の手順](#絵コンテの再生成)は付録)
- ワンテイク撮影スクリプト: [shooting/sequence.js](shooting/sequence.js)(画面収録して撮る)
- 自動撮影・書き出し: [shooting/capture.mjs](shooting/capture.mjs) → [shooting/telops.mjs](shooting/telops.mjs) → [shooting/encode.mjs](shooting/encode.mjs)([手順](#自動で撮る画面収録なし))

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 伝えること | (1) ブラウザで歩き回れる 3D の錯視美術館であること (2) 「ヒントを見る」で種明かしが起こる体験 (3) 古典の間と Fable の間の 2 室があること |
| 想定する用途 | X などの SNS 投稿、README への埋め込み、公開版へのリンクの導線 |
| 尺 | 15.0 秒(30 fps で 450 フレーム) |
| 画面 | 1920×1080、16:9。縦動画が必要なら別途(§8) |
| 音 | アプリに音はない。BGM は任意(入れるなら控えめな環境音かピアノ。権利を確認する) |
| 素材 | 公開版 <https://maoku.github.io/Fable51OpticalIllusion/> または `npm run dev` のローカル。`?quality=high` で品質ティアを固定する |

## 2. 構成の方針

- **「見える → 種明かし」の 2 拍を 1 カットにする。** 各カットは、まず錯覚が見えている状態を短く見せ、次に「ヒントを見る」相当の演出で種明かしをする。この繰り返しで「ヒント」の体験が伝わる。
- **動画で動きが伝わる展示を選ぶ。** 視点が回る(C2)、球が転がる(F2)、覗き込むと視差が出る(F5)、カメラが飛ぶ(F6)の 4 つ。ポスター系(C4〜C6)や、静止画で見比べる F1・F3・F7 は外す。
- **種明かし演出の時間はアプリ側で固定。** 各展示の `durationMs`(C2 2.6 s、F2 1.6 s、F5 1.6 s、F6 3.6 s)に「見せる間」を足してカット尺を決める。演出を早送りしない(`?timescale` は使わない)。
- **視点固定型の展示は、演出の前に 0.5 秒の「寄り」が入る。** ヒントを開くと推奨視点へ 0.5 秒で移動してから演出が始まる(C1・C2・C7・C8・F1・F5・F6)。すでに推奨視点にいればその 0.5 秒は静止になる。この 0.5 秒は「錯覚を見せる間」として尺に含めてある。
- **切り替えはハードカット。** カット間はワープで瞬時に切り替える。フェードやワイプは入れない。
- **HUD は隠して収録し、テロップは編集で載せる。** 「ヒントを見る」ボタンの代わりに、演出の開始時にチップ状のテロップを出す。

## 6. 収録手順

### 環境

- GPU のある実機(MacBook など)と最新の Chrome。CI や SwiftShader では fps が出ないので使えない。電源に繋ぎ、他のタブとアプリを閉じる。
- 事前に `?quality=high&stats=1` で開き、左下の統計で 60 fps 前後・ティア high が出ることを確認する。出なければ §8 を見る。確認後は `stats=1` を外す。
- 画面を 16:9 にする。DevTools(Cmd+Option+I)→ 右上のメニューから「Undock into separate window」で別ウィンドウにし、デバイスツールバー(Cmd+Shift+M)で Responsive 1920×1080 を指定する。DPR は 1(Retina で fps が出ないときも 1)。ページ側のウィンドウはできるだけ大きくし、収録は 1920×1080 の描画領域だけを範囲指定する。
- URL: `https://maoku.github.io/Fable51OpticalIllusion/?quality=high`(ローカルなら `http://localhost:5173/?quality=high`)。
- 操作説明を「はじめる」で閉じる。マウスカーソルは収録範囲の外(DevTools のウィンドウ)へ置く。

### ワンテイクで撮る(推奨)

1. macOS の画面収録(Cmd+Shift+5 → 「選択部分を収録」で 1920×1080 の範囲を指定)か OBS(60 fps)を開始する。
2. DevTools のコンソールに [shooting/sequence.js](shooting/sequence.js) の中身を貼り付けて Enter。
3. HUD が消え、入口の開始姿勢で静止する。F2 の球の位相を合わせるため最大 6.5 秒待ったあと、5 カットが自動で進む(合計 15.4 秒)。
4. 最後の俯瞰で止まったら収録を停止する。コンソールに各カットの開始時刻が出る(`__shootLog` にも残る)。カット表とのずれが 0.2 秒を超えていたら fps 不足なので撮り直す。
5. `__shootRestore()` で HUD とヒントを元に戻す。

スクリプトがやっていることは次のとおりで、手動で撮るときの操作と同じ。

- `document.getElementById('ui').style.display = 'none'` で HUD を隠す
- `__museum.warpTo(id)` で展示の推奨視点へワープ(展示一覧から選ぶのと同じ)
- `__museum.hints.open(id)` で種明かし(E キーと同じ)、`__museum.hints.hintPlayer.progress` が 1 になるまで待つ
- `__museum.player.moveTo(pose, 秒)` でドリー、`__museum.player.teleport(pose)` で瞬間移動
- 時間はシーン時間 `__museum.loop.elapsed` で測る

### 自動で撮る(画面収録なし)

画面収録の代わりに、時間を仮想化してフレームを 1 枚ずつ書き出す方法。`requestAnimationFrame` と
`performance.now` を差し替えて 1/60 秒ずつ手で進めるので、描画に何ミリ秒かかってもカット尺はずれない
(fps 不足による撮り直しが起きない)。テロップも焼き込むところまで自動で通る。実機 GPU の Chrome を
Playwright が headed で起動するので、収録中はウィンドウを触らない。

```bash
npm run dev        # 別のシェルで開発サーバーを起動しておく
npm run pv:all     # フレームを撮り直して書き出す(約 5 分)
npm run pv         # テロップだけ直したとき: 既存のフレームから書き出す(約 1 分)
```

- `npm run pv:capture` … [capture.mjs](shooting/capture.mjs)。900 枚の PNG を `Docs/screenshots/pv/frames/` に(約 4 分)
- `npm run pv` … [telops.mjs](shooting/telops.mjs) で §5 のテロップを透過 PNG に焼き、
  [encode.mjs](shooting/encode.mjs) で 15.0 秒の MP4 と README 用 GIF を書き出す
- `npm run pv:all` … 上の 2 つを続けて実行する

出力は `Docs/screenshots/pv/`(git 管理外)。カットの発火時刻は `pv/timeline.txt` に残る。
カット表の設計値との差は 0。編集(頭と尾を切る、テロップ、フェード)は encode.mjs が §7 のとおりに行う。
テロップの文言と時間は telops.mjs の `TELOPS` にある。文言だけ直したなら `npm run pv` で撮り直しは要らない。
素材のフレームは 820 MB あるので、撮り直す予定がなければ `rm -rf Docs/screenshots/pv/frames` で消してよい。

- 品質: `?quality=high` で起動し、動的調整を止めて pixelRatio を 1 に固定する。ティアが high 以外に
  なったら警告が出る。
- F2 の球の位相は、撮影開始時に `ballT` を 3.2 に置いて合わせる(3.2 + 4.9 = 8.1、周期 6.5 で 1.6)。
- README 用の GIF は 720×405 / 12 fps / 96 色。960×540 / 15 fps では 15 MB を超えるため(§7 の
  10 MB に収まらない)。

### 1 カットずつ手動で撮る

編集で繋ぐ前提なら、カットごとに撮ってもよい。Tab キーで展示一覧を開いて展示を選ぶと推奨視点へワープする。E キー(または「ヒントを見る」)で種明かし、もう一度で元に戻る。HUD を消したいときは上のコンソール操作を使う。各展示の推奨視点と演出時間は付録の表にある。

## 7. 編集指示

- 収録の頭(スクリプトの位相待ち。開始姿勢で静止している部分)を切り、カット 1 のドリーが始まるフレームを 0.0 s にする。
- 尾は 15.0 s で切る(スクリプトは 0.6 秒余分に保持している)。
- カット間はそのまま(ハードカット)。トランジションは入れない。
- テロップは §5 のとおり。0.15 秒のフェードイン・アウトを付ける。
- 音: BGM を入れる場合は −18 LUFS 程度に抑え、13.0 s から 15.0 s でフェードアウト。効果音は入れない。
- 書き出し: H.264 MP4、1920×1080、30 fps(素材が 60 fps なら 60 fps でも可)、15.0 s。README 用は 960×540 の GIF(15 fps、10 MB 以下)か、MP4 へのリンク。

## 8. リスクと対策

| リスク | 対策 |
| --- | --- |
| fps 不足で演出がカクつく・カット尺が伸びる | 実機 GPU、他のアプリを閉じる、DPR 1、`stats=1` で事前確認。`__shootLog` のずれが 0.2 秒を超えたら撮り直す |
| F2 の球がカットの開始で止まっている・消えている | スクリプトが位相を合わせる。手動時は球が現れてから 1.5〜2 秒後に E |
| F5 の井戸が静止画になる | low ティアの仕様。`?quality=high` を付ける。fps が出ないなら `mid` |
| C2 の角柱が白飛びする | 高ティアのブルーム。気になれば `?quality=mid` |
| 演出前の 0.5 秒の静止が長く感じる | 視点固定型の展示の仕様(推奨視点への移動)。尺に含めてある。詰めたい場合は編集で 10 フレーム程度切ってもよい |
| 縦動画(9:16)が必要 | アプリは縦長画面で垂直画角を最大 92° まで広げるため構図が変わる。ワープ先は同じでよいが、テロップ位置とカット 1 のドリー量は別途決める |
| 公開版とローカルで見た目が違う | 同じビルド(`main`)なら同じ。撮影の直前に `git log` で公開版のコミットを確認する |

## 付録 B: 絵コンテの再生成

`Docs/screenshots/` は git 管理外なので、絵コンテの画像は手元で生成する。開発サーバーを起動してから、[shooting/storyboard.mjs](shooting/storyboard.mjs) を [shooting/storyboard-shots.json](shooting/storyboard-shots.json) で走らせる。

```bash
npm run dev
BASE=http://localhost:5173 node Docs/shooting/storyboard.mjs Docs/shooting/storyboard-shots.json
```

SwiftShader(CPU 描画)で `quality=high` を強制し、HUD を隠して 1280×720 で撮る。1 枚あたり 5〜15 秒かかる。`hintT` を指定した要素は、演出がその進行度に達した時点で時間を止めて撮る(カット 2 と 5 の「演出の途中」)。
